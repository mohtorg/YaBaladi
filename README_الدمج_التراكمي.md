# حزمة الدمج التراكمي (الجولات 1 إلى 4)
انسخ محتويات هذا المجلد فوق مشروعك بالهيكل نفسه (احتفظ بنسخة احتياطية أولاً)، ثم:
1. احذف يدوياً: `lib\core\utils\reset_ratings_util.dart` و`seed.sh`.
2. `flutter pub get` (أُضيف firebase_app_check) ثم `flutter analyze`.
3. أنشئ `android\key.properties` ومفتاح التوقيع (انظر README الجولة 2 في الحزمة السابقة).
4. انشر: `firebase deploy --only firestore:rules,firestore:indexes,storage` — **بعد** نجاح اختبارات القواعد.
5. App Check: سجّل رمز debug في الكونسول عند الاختبار على جهاز التطوير، وأبقه في وضع المراقبة أسبوعاً.
6. انقل الوثائق القديمة (PROJECT_STATE وSESSION_STATE وRESUME وMVP) إلى docs/archive واعتمد `دليل_المشروع_الشامل.md`.
**الاختبارات مؤجَّلة بقرارك**: لم يُشغَّل شيء مما سبق. أول ما يُنفَّذ عند العودة: `cd firebase_rules_tests && npm install && npm run test:baseline && npm test`.
**التراجع**: أعد ملفاتك الأصلية من النسخة الاحتياطية، وأعد نشر القواعد القديمة من `firebase_rules_tests/baseline/`.

## إضافة الجولة 7 (مسار التاجر)
- `firestore.rules`: السماح لتاجر المكان بالردّ على تقييماته (حقلا merchantReply وmerchantRepliedAt فقط)، ومنع صاحب التقييم من كتابة هذين الحقلين على تقييمه.
- `add_branch_screen.dart`: الفرع الجديد يُنشأ `isApproved:false` (يعتمده الأدمن) لأن القواعد تمنع الاعتماد الذاتي.
- اختبارات جديدة: ردّ التاجر، الفرع، بثّ الإشعارات.
- ملاحظة: بثّ «عرض جديد» لكل المستخدمين من شاشة العروض صار مرفوضاً بالقواعد (كان تاجر واحد يستطيع إغراق كل المستخدمين). يُنقل لاحقاً إلى اعتماد الأدمن/الخادم.

## إضافة (إدارة الأدوار)
`tools/admin_roles.js`: تعيين الأدمن والمشرف وسحب الصلاحية من جهازك بحساب الخدمة، مع Custom Claim وسطر تدقيق. القواعد الحالية لم تتغير (تقرأ الدور من مستند المستخدم). لم يُجرَّب.

## إضافة (دورة التقييمات)
`firestore.rules`: منع تقييم مالك المكان لمكانه بقاعدة (كان في الواجهة فقط) + اختبار. لم يُجرَّب.
