# يا بلدي — الجولة 1: تحصين قواعد Firestore وStorage (P0-أ إلى P0-د)

## ما الذي تغيّر؟
| الملف | التغيير |
|---|---|
| `firestore.rules` (إصدار 7.0) | places وusers وratings وplace_aggregates وaudit_logs وnotifications، وإضافة قواعد owner_claim_requests وmoderation_logs وrating_revisions وsystem_events وusers/{uid}/fcm_tokens |
| `storage.rules` (إصدار 2.0) | صور المكان لمالكه أو الأدمن فقط؛ فصل الحذف عن الرفع |
| `firebase_rules_tests/` | 41 اختباراً بمحاكي Firebase، ونسخة القواعد الأصلية في `baseline/` لإثبات فشل الثغرات |

## لماذا؟
كل منطق الثقة والإشراف يعمل من العميل، والقواعد كانت تسمح لأي مسجّل بإنشاء مكان معتمد، وتزييف التقييم، وكتابة صور أي مكان، وتزوير الإشعارات. وكانت مجموعات الإشراف والمطالبة بلا قواعد فتُرفض كلها بالرفض الافتراضي.

## كيف تُختبر (على جهازك: يلزم Node وJava)
```
cd firebase_rules_tests
npm install
npm run test:baseline    # على القواعد الأصلية: يُتوقع فشل اختبارات الثغرات (هذا هو الدليل)
npm test                 # على القواعد الجديدة: يُتوقع نجاح الكل
```
ثم انشر: `firebase deploy --only firestore:rules,storage`

## كيف تتراجع؟
أعد القواعد من `baseline/firestore.rules` و`baseline/storage.rules` وانشرها.

## ما لم أتحقق منه (صراحةً)
- **لم أشغّل الاختبارات**: تنزيل المحاكي محجوب في بيئتي. القواعد والاختبارات لم تُجرَّب بعد، وفحصتُ توازن الأقواس فقط. لا تنشر قبل نجاح `npm test` عندك.
- لم أشغّل `flutter analyze` (Flutter غير متاح عندي).
- قواعد Storage تقرأ Firestore (`firestore.get`)، وقد يطلب Firebase منحك صلاحية IAM عند أول نشر.

## تغييرات سلوكية متوقعة (اقرأها قبل النشر)
1. **زيادة viewCount**: لمسجّل فقط (+1). الزائر غير المسجّل لن يُحتسب.
2. **الحذف النهائي لسجل التدقيق** (`hardDeleteLog`) سيفشل بالرفض؛ سجّل التدقيق إضافة فقط وتبقى الأرشفة والحذف الناعم. يلزم إخفاء زر الحذف النهائي في الواجهة (جولة لاحقة).
3. **الإشعارات**: الإنشاء للمشرف/الأدمن فقط؛ إشعار التاجر من `manage_offers_screen` سيفشل حتى ينتقل للخادم.
4. **حظر المستخدم** يقتصر على الأدمن (كما كان)؛ المشرف لا يستطيع كتابة users.
5. **حقل trustScore وhasConfirmedReports** يبقى محجوباً عن العميل (كما كان).

## حدود معروفة (لا تُعدّ إغلاقاً كاملاً)
متوسطات التقييم ما زالت تُكتب من العميل بنطاق وخطوة محدودين: المتلاعب يستطيع تحريكها بخطوات صغيرة متكررة. الحل الجذري نقلها إلى الخادم (حزمة P1) ويحتاج **قرارك بشأن خطة Blaze**. وتقييم واحد لكل مستخدم لكل مكان لم يُفرض بعد (يحتاج معرّفاً حتمياً أو خادماً). وPIN المكان ما زال في وثيقة عامة (P1).
